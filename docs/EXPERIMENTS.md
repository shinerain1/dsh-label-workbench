# 实验结果与解释

日期：2026-11-10。所有文本是合成客服工单，人工审核是固定模拟事件。原始模型推理和本机凭据不公开；保留可运行脚本、协议、逐组统计和独立审计结果。

## 1. 确定性规则变更与故障注入

源：[预案](PROTOCOL.md)、[脚本](../scripts/benchmark.py)、[原始统计](benchmark-results.json)。三个配对规模为 120 / 360 / 1200 条。标准改变包括“退货”归类移动、新增“退钱/破损”和顺序规则交叠，不只是新增关键词。

1200 条的结果：

| 指标 | 简易 JSON 脚本 | 有完整保护的脚本 | 工作台 |
|---|---:|---:|---:|
| 遗漏复核 | 192 | 0 | 0 |
| 最终混入旧版本结果 | 100 | 0 | 0 |
| 当前人工结果被机器覆盖 | 40 | 0 | 0 |
| 最终错误标签 | 240 | 0 | 0 |
| 新规则机器计算条数 | 300 | 1160 | 527 |
| 人工再次确认条数 | 40 | 40 | 40 |
| 保留人工历史条数 | 80 | 80 | 80 |
| 已验证可追溯 ZIP | 不提供 | 不提供 | 通过 |

简易脚本只按全局新增关键词筛选，漏掉关键词从某一类移动到另一类的情况，回调又没有版本门禁。它不是“DSH 的能力上限”。完整保护脚本全部重做机器标签且拒绝旧回调，**同样解决一致性问题**。

工作台在三个规模中上述四种错误均为 0，安全沿用分别为 68 / 203 / 673 条。1200 条实验比全量保护基线少计算 633 条（约 54.6%），但它依赖**完整可执行的规则标准**；不是语义影响筛选的准确率证据。自然语言规则变动直接全量复核，已单独测试。

工作台有 SQLite、日志和 ZIP 成本，1200 条整段流程约 2.19 秒；内存脚本不到 0.002 秒。两种持久化和产出不同，此计时不能当作公平速度比赛，更不能声称插件加速本地关键词判断。没有付费标注模型调用，减少计算条数也不等于实测节省 API 费用。

## 2. 真实 DSH + 模型对照

源：[预案](AGENT-PILOT-PROTOCOL.md)、[运行/审计代码](../scripts/agent_pilot.py)、[结果](agent-pilot-results.json)。模型 deepseek-official/deepseek-flash，low；两组各 1 个 Session、2 轮、24 条文本，第二轮启动新的 DSH 进程并复用 Session ID。DSH commit `8bd073392eef6f54e921a093b95076248eb08cbb`。

普通脚本组可以自己写完整保护逻辑，没有使用确定性实验的弱基线脚本。两组给出的任务和初始数据相同，均知道晚到回调存在。这是小型演示，不是盲测。

[合成交付证据](evidence/manifest.json)提供两组状态、交接报告、普通脚本组由 DSH 实际写出的 workflow.py 及输入。发布时仅隐去本机路径；同时记录源文件和发布文件的哈希。没有发布模型推理原文。

| 指标（两轮合计） | DSH + 普通 Python/JSON | DSH + 插件 |
|---|---:|---:|
| 最终 24 条记录独立审计 | 通过 | 通过（另核验 SQLite） |
| 两条人工记录保留、待新规则复核 | 通过 | 通过 |
| 未复核时阻止最终导出 | 通过 | 通过 |
| 第一轮 | 达到 8192 输出上限，未交付 | 完成 |
| 第二轮新进程 | 继续完成并复查 | 恢复并复查 |
| 工具调用 | 24 | 36 |
| 非缓存输入 tokens | 19,406 | 33,196 |
| 输出 tokens | 21,172 | 14,056 |
| 缓存读取 tokens | 431,744 | 698,752 |
| provider totalTokens | 472,322 | 746,004 |
| 两轮墙钟 | 208.937 秒 | 120.734 秒 |

**没有发现插件在最终正确率上的优势；插件总 token 和工具调用更多。** 单次运行中它较早交付且少生成代码，但不能推断普遍节省成本/时间。缓存和输出价格不同，本项目不将 totalTokens 转成费用。普通脚本第二轮完成也说明 DSH 可以独立实现可靠流程；第一轮 max-tokens 失败保留，没有剔除重跑。

两组都保留 2 条待人审记录，因此本次正确行为是拒绝导出，不是伪造“全流程已人审完成”。真实人的标注时间、审核质量和意见一致性尚未测量。

## 3. DSH 特性与工程验证

[真实 PTC 测试](dsh-ptc-results.json)在 DSH 正式工具执行器和 PTC runtime 上执行：17 个插件工具；1 次外层 run_code / 11 次内层工具完成建项目、旧任务领取、新规则切换、隔离回调和导出。插件卸载后工具消失，重载同一 Session 可恢复项目，同一创建键重放不重复建项目。这里模型调用为 0；不把 PTC 测试混作模型 A/B。真实进程恢复另由上节证明。

Python 测试覆盖真实独立 worker 延迟返回、并发领取、过期重领、重复提交、取消后返回、版本冲突、人审修订冲突、批次回滚、人工通道、自然语言全量复核、Label Studio JSON 往返、词汇变更、导出阻断与损坏检测。Node 测试使用真实 Python RPC，而非假的后端。

浏览器视觉检查未完成：浏览器接入服务不可用，Windows UI 工具无法可靠识别当前 URL，检查被停止。未绕过限制。审核页面的 HTTP 成功提交、无 token 拒绝、过期表单冲突已有自动测试；不能据此声称完成浏览器视觉验收。

## 当前结论

已增加 [CFPB 真实分类变更案例](CFPB-CASE-STUDY.md)：1,200 条公开真实投诉，三个固定故障种子、三组实现、独立后台进程。覆盖式脚本每次混入 120 条旧版本、80 条旧类别，并覆盖 24 条当前审核来源；插件和有保护脚本均为 0。标签由官方分类映射提供、审核是模拟事件，所以不代表 NLP 准确率或真实人审研究。自然语言全量复核多处理了 392 条未变机器标签；不宣称节省成本。另有真实 DSH/PTC 的 90 条数据接入验证，模型调用为 0。

可以继续作为“可信规则变更后的流程工作台”开发；目前证据支持版本/并发完整性与持久恢复，不能证明自动语义影响识别、比成熟标注平台更强、或普遍更省钱。

优先后续事项：自然语言规则影响候选排序但保留人工放行；真实数据多次随机顺序的 Agent 对照；缩减工具上下文/结合 PTC 的成本实验；真正 Label Studio 服务端联调；多人身份与审核权限；浏览器和跨平台验收。首版不会为了少复核而默认启用未经验证的语义筛选。
