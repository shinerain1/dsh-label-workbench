# 标注规则变更实验预案

首次运行前固定本文件和案例生成脚本 SHA-256。日期：2026-11-10。

首版范围：本地不可变文本、单标签分类。研究版本切换后数据一致性，不验证通用 AI 标注准确率。

确定性对照采用自建中文客服意图数据、两个明确可执行的规则版本以及固定的人工纠正事件。三种实现收到相同事件顺序：

1. 普通逐行覆盖的 JSON 标注脚本：保留标签、规则版本、人工标记，但回调无事务版本检查；常见简易基线，不代表所有脚本或 DSH 能力。
2. 有保护的普通脚本：完整版本检查、人工保护、规则变更后全部重做；避免只和弱基线比较。
3. 工作台：事务切换、租约、规则/记录修订校验、保守影响筛选、人工保护、导出检查。

每次先完成 v1 标注；创建一个延迟旧任务；完成人工纠正；切换 v2；处理新任务；延迟 v1 回调最后到达。记录遗漏复核、旧结果混入、人工结果覆盖、重新标注量、人工确认量和耗时。采用三个固定规模/种子，所有不利结果保留。人工操作是确定性模拟事件，不称为真实标注员研究。自然语言规则单独测试必须全量复核；不声称实现语义影响预测。

故障验证包括真实独立后台进程晚到、取消后返回、租约过期/重领、重复回调、审核页面版本/修订冲突、DSH 重启恢复、导出阻断和产物篡改。若有真实 DSH+模型对照，另行标记模型、轮次、预算、完整率和 usage；不把无模型 PTC 测试说成 Agent A/B。

判定标准：工作台在预定事件中无旧结果成为当前标签、无机器覆盖人工审核、导出不存在未复核记录。影响筛选在可执行规则集上对实际标签变化无漏选；自然语言变化全选、准确性问题不被隐藏。若有保护的脚本也正确，明确报告其同样能解决问题；插件贡献是把流程固化为可复用 DSH 工具，而非宣称独有算法。
