# CFPB 真实分类变更回放：实验预案

预先固定于 2026-11-10；先采集、冻结样本，再运行对照。脚本将预案、执行脚本和数据清单的 SHA-256 写入结果。预先固定不等于外部注册。

## 场景和来源

下游分析团队希望把历史消费者投诉统一到 2023 年 8 月的产品分类。CFPB 的表单确实于 **2023-08-24** 把 `Credit card or prepaid card` 拆分为 `Credit card`、`Prepaid card`；官方数据库保留提交时的原始选择。我们建立派生标签，不修改官方记录。

- [2023 官方分类说明](https://files.consumerfinance.gov/f/documents/cfpb_consumer_complaint_form_product_issue_options_August_2023_FINAL.pdf)，正文第 1–2、6、26 页及附录 A。
- [官方公开投诉归档](https://www.consumerfinance.gov/foia-requests/foia-electronic-reading-room/cfpb-consumer-complaint-database-narratives-archive/)，使用 November 2022 through August 2023 ZIP。
- [数据库使用说明](https://www.consumerfinance.gov/data-research/consumer-complaints/)：投诉不是所有消费者的代表性样本；产品分类是消费者选择，不是经专家核验的文本标签。

归档真实，分类变更真实；后台迟到、审核、重启和导出时机是我们控制的回放事件，不是 CFPB 内部运行日志或已部署案例。

## 样本固定

取归档中日期在 `[2023-01-01, 2023-08-24)`、有非空公开叙述、文本不超过插件 50,000 字符上限的记录。只选择旧信用卡/预付卡产品和未改变产品级分类的 `Checking or savings account`。按官方子产品定义确定拆分后的参考产品，未知子产品显式报告并排除，不能默默猜测。

每个目标类别取 SHA-256(`20230824:投诉ID`) 排序最小的 400 条，共计划 1,200 条；不足则报错，不改变抽样标准。这是便于覆盖少数类别的分层样本，不估计真实投诉占比。保存所有纳入 ID、日期、原始产品/子产品、叙述哈希、派生标签，原始叙述仅放本地忽略目录。全 ZIP 哈希及排除计数一同保存。

三组得到相同 v1/v2 参考标签流。标签由官方分类映射提供，**不用它评估 NLP 标注准确率**。插件接收真实叙述，通过冻结记录 ID/hash 关联标签；并不因为拿到参考答案而获得语义判断能力。模拟审核使用相同参考标签，测是否保留审核来源和历史，不冒充真实标注员实验。

## 三组与事件顺序

1. **普通覆盖式 JSON 脚本**：持久化标签、版本、审核来源；常规更新跳过人工结果。按旧标签是否仍属于新词表筛选，未失效的机器标签沿用。回调逐条覆盖，不检查任务版本/审核修订；直接导出快照。它是明确的简易实现，不能代表所有 DSH/脚本。
2. **有保护的 JSON 脚本**：规则变化全量重新处理；检查旧版本，保留人工结果，待复核时拒绝导出，持久化完整状态。作为能够解决问题的强基线。
3. **当前插件**：自然语言规则变化全量复核，正式 job/claim/submit 接口、事务、版本/修订校验、人审保护和导出验证。不给插件添加为此样本量身定做的筛选器。

固定种子 7、11、19，各在同一个样本上选择每类 8 条模拟审核（共 24）及每类 40 条迟到记录（共 120，含全部审核记录）。这三次改变故障落点，不是三个独立总体样本。

事件：建立 v1；独立后台进程领取 v1 的 120 条并等候；完成 v1；审核 24 条；切换 v2；立即尝试导出；分批处理非人工记录并再次尝试导出；确认 24 条人工 v2；重建服务/从磁盘恢复状态；放行旧进程实际提交；重放同一旧回调；完成最终导出及独立审计。worker 的领取和迟到提交在不同 OS 进程完成，通过文件屏障控制顺序，不靠碰巧 sleep 获得结果。

## 指标与判定

- 当前标签与派生参考产品不一致数；当前结果版本错误数；当前人工来源丢失数。
- 应改标签的记录中未被选入复核的数量；待复核时导出是否拒绝。
- 迟到回调被隔离数、重复回调是否增加决策数、历史审核是否完整。
- 新机器标签处理量、人工确认量，以及未变类别也被复核的数量。不能把 Python 映射次数称作 LLM token 或人工分钟。
- 最终 ZIP 的记录、版本、哈希和历史验证。逐记录无叙述审计表可独立重算主要数字。

假设：插件应在这些规定事件中保持一致；有保护脚本也应做到。普通脚本是否遗漏复核取决于真实分类变化，允许为零，不能刻意构造遗漏。自然语言变化全量复核可能增加成本，必须报告。

另用真实 DSH 的正式工具/PTC 在同一数据子集重放迁移、迟到隔离及 Session 恢复，标记 **无模型调用**。它验证 DSH 接入，不替代真实 Agent A/B。已有合成数据 Agent 试验结果单独保留，不与本实验混算。

不能据此声称：提高标签语义准确率、在所有业务上有收益、智能识别所有规则影响、优于完善的普通脚本，或实际获得企业生产收益。
